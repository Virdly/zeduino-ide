# ИИ-чат: настройка и API

ZedArduino IDE не имеет собственного AI-бэкенда. Чат работает с любым сервером, совместимым с OpenAI Chat Completions: пользователь указывает адрес, ключ и модель. Ключ хранится только локально, запросы уходят только на указанный endpoint.

Документ описывает фактическое поведение 1.0.0. Общая архитектура — в [ARCHITECTURE](ARCHITECTURE.md), безопасность — в [SECURITY](../SECURITY.md).

## 1. Настройка

«Настройки → ИИ»:

| Поле | По умолчанию | Примечание |
| --- | --- | --- |
| Адрес API (`baseUrl`) | `https://api.deepseek.com/v1` | без завершающего `/`; можно указать полный URL до `/chat/completions` |
| API-ключ | пусто | сохраняется в `settings.json`; поле скрыто, есть кнопка показа |
| Модель | `deepseek-chat` | ровно та строка, которую ждёт провайдер |
| Системный промпт | краткий промпт про Arduino и инструменты | можно сбросить кнопкой |
| Temperature | `0.3` | UI: 0–2, шаг 0.1 |
| Max tokens | `4096` | UI: 128–128000, шаг 128 |
| Инструменты | включены | добавляет `tools` и `tool_choice: "auto"` в запрос |

Типичные адреса (ключи — заглушки, не настоящие):

```text
https://api.openai.com/v1
https://api.deepseek.com/v1
http://127.0.0.1:11434/v1        # Ollama, OpenAI-совместимый режим
http://127.0.0.1:1234/v1         # LM Studio
http://127.0.0.1:8787/v1         # локальный mock из раздела 8
```

Ключ для локального сервера всё равно обязателен: main отклоняет пустой `apiKey` до запроса. Для mock подойдёт `sk-REPLACE_ME`.

### Как строится URL

Код в `src/main/ai.ts`:

```ts
const base = baseUrl.trim().replace(/\/+$/, '')
if (base.endsWith('/chat/completions')) return base
return `${base}/chat/completions`
```

То есть `https://api.example.com/v1` → `https://api.example.com/v1/chat/completions`, а полный URL используется как есть. Никаких запросов к `/models` или другим endpoint нет.

## 2. Формат API

Запрос:

```http
POST <baseUrl>/chat/completions
Content-Type: application/json
Authorization: Bearer <apiKey>

{
  "model": "deepseek-chat",
  "messages": [
    { "role": "system", "content": "..." },
    { "role": "user", "content": "..." }
  ],
  "stream": true,
  "temperature": 0.3,
  "max_tokens": 4096,
  "tools": [ ... ],
  "tool_choice": "auto"
}
```

`tools` и `tool_choice` присутствуют только при `toolsEnabled: true`. Другие параметры (top_p, stop, seed и т. п.) не передаются.

История сообщений преобразуется так:

| Сообщение UI | Что уходит в API |
| --- | --- |
| `system` в истории | игнорируется; системный промпт берётся только из настроек |
| `user` | `{ role: "user", content }` |
| `assistant` без tool calls | `{ role: "assistant", content }` |
| `assistant` с tool calls | `{ role: "assistant", content, tool_calls: [{ id, type: "function", function: { name, arguments } }] }` |
| `tool` | `{ role: "tool", tool_call_id, content }` |

Ожидается ответ в формате SSE (`Content-Type: text/event-stream`), строки `data: <json>`, завершение `data: [DONE]`. Поддерживается стандартная структура OpenAI:

```json
{
  "choices": [{
    "index": 0,
    "delta": { "content": "текст" },
    "finish_reason": null
  }]
}
```

и для инструментов:

```json
{
  "choices": [{
    "index": 0,
    "delta": {
      "tool_calls": [{
        "index": 0,
        "id": "call_1",
        "type": "function",
        "function": { "name": "read_file", "arguments": "{\"path\":\"Blink.ino\"}" }
      }]
    },
    "finish_reason": null
  }]
}
```

Аргументы могут приходить фрагментами: IDE склеивает `id`, `name` и `arguments` по `index`. Строки-комментарии SSE (`: keep-alive`), пустые строки и строки без `data:` игнорируются; битый JSON пропускается. Поле `usage` не используется.

## 3. Стриминг

1. Пользователь отправляет сообщение → renderer создаёт `requestId` (`req_...`) и placeholder ассистента.
2. Main делает `fetch` с `AbortController` и читает `response.body` через `ReadableStream`.
3. Каждый `delta.content` отправляется как `ai:chunk`; renderer дописывает текст в активное сообщение.
4. По завершении — `ai:done` с `content` и `finishReason`; при наличии tool calls — сначала `ai:tools`, затем `ai:done` с `finishReason: "tool_calls"`.

Особенности:

- Панель чата можно закрыть во время стрима: подписки живут на уровне модуля, ответ продолжит собираться; при открытии панели текст уже будет.
- `aiBusy` в общем store используется статус-баром; сам чат хранится в отдельном Zustand-store и **не сохраняется** между запусками приложения.
- Ориентировочный размер переписки показывается как `≈N ток.` (оценка `ceil(сумма символов / 4)`), это не точный подсчёт токенов.

## 4. Согласование инструментов

Инструменты — не автоматические действия. Каждый вызов показывается карточкой:

- имя и описание (`read_file` и т. д.), путь относительно корня проекта;
- сворачиваемые аргументы JSON и результат;
- кнопки «Разрешить» / «Отклонить» для вызова;
- «Разрешить всё» / «Отклонить всё» для пакета;
- статусы: ожидает решения, выполняется, разрешено, отклонено, ошибка;
- для `delete_file` карточка помечена как опасная.

Поток:

```text
model → ai:tools → карточки (pending)
                    ├─ пользователь разрешает → ai:exec-tool → результат
                    └─ пользователь отклоняет → "Отклонено пользователем"
после решения по всем вызовам:
  сообщения role=tool добавляются в историю
  автоматически отправляется следующий ai:chat
```

Пока пакет не закрыт, новое сообщение отправить нельзя. Если аргументы не парсятся как JSON-объект, вызов нельзя выполнить — карточка показывает ошибку. Если проект не открыт, кнопки заблокированы: инструменты работают только внутри проекта.

Важно: модель может вернуть и текст, и tool calls в одном ответе; текст сохраняется, затем запрашивается согласование.

## 5. Инструменты и схемы аргументов

Определения лежат в `src/main/ai.ts` (`TOOL_DEFS`):

| Имя | JSON Schema аргументов | Результат |
| --- | --- | --- |
| `read_file` | `{ "path": string }`, обязателен `path` | текст файла; больше 120 000 символов обрезается с пометкой |
| `write_file` | `{ "path": string, "content": string }`, обязательны оба | запись целиком; родительские папки создаются; файл может быть новым |
| `create_file` | `{ "path": string, "content"?: string }`, обязателен `path` | создание; если файл существует — ошибка |
| `delete_file` | `{ "path": string }`, обязателен `path` | удаление файла; **если путь указывает на папку, удаление рекурсивное** |
| `list_dir` | `{ "path"?: string }` | имена файлов и папок; `""` или отсутствие — корень проекта |

Все пути — относительно корня открытого проекта, в POSIX-виде (`src/foo.h`) или с обратными слешами; `resolveInside` нормализует их. Абсолютные пути и `..` за пределы проекта отклоняются.

Ограничения `WorkspaceService`: чтение файла больше 8 МБ отклоняется (это ошибка редактора, не инструмента); листинг пропускает скрытые элементы; `write_file`/`create_file` не делают резервных копий. `delete_file` не отправляет файл в корзину — удаление необратимо.

## 6. Песочница

Песочница реализована в main, а не в renderer, поэтому её нельзя обойти подменой UI:

```ts
// WorkspaceService.resolveInside
const normalised = relPath.replace(/\\/g, '/').replace(/^\/+/, '')
const abs = path.resolve(this.root, normalised)
const rootWithSep = this.root.endsWith(path.sep) ? this.root : this.root + path.sep
if (abs !== this.root && !abs.startsWith(rootWithSep)) throw new Error('Путь вне папки проекта')
return abs
```

Правила:

- проект должен быть открыт (`workspace.getRoot()` не пуст);
- путь разрешается относительно корня проекта;
- побег через `..`, абсолютный путь или путь на другой диск отклоняется;
- проверяется префикс канонического `path.resolve`, но **не** `realpath`: симлинк/джанкшен внутри проекта теоретически может указывать наружу. Это известное ограничение; не открывайте недоверенные проекты с подозрительными ссылками.

Инструменты не запускают команды, не компилируют и не загружают скетчи. Компиляция/загрузка — отдельные действия пользователя через `arduino-cli`.

## 7. Приватность и хранение ключа

- Ключ хранится в `%APPDATA%\ZedArduino IDE\settings.json` в открытом виде (JSON, без шифрования). Файл доступен пользователю Windows, у которого есть доступ к профилю.
- Ключ не передаётся по сети никуда, кроме заголовка `Authorization: Bearer` запроса к указанному `baseUrl`.
- В репозиторий ключ не попадает: `settings.json` лежит вне проекта. Не копируйте его в issue и не делайте скриншоты с видимым ключом.
- История чата хранится в памяти renderer и исчезает при закрытии/перезапуске приложения. Приложение не пишет логи чата на диск.
- В запрос уходят системный промпт, история переписки и результаты инструментов (то есть содержимое прочитанных файлов). Это видит выбранный провайдер; его политика хранения — вне контроля IDE.
- Собственной телеметрии, аналитики и «домашних» запросов нет. `arduino-cli` может обращаться в сеть для индексов/ядер/библиотек — это не связано с ИИ.

## 8. Локальный mock-сервер без платного ключа

Пример совместимого сервера на Node.js 20 (без зависимостей). Создайте `mock-openai.mjs` вне репозитория или в игнорируемой папке и запустите `node mock-openai.mjs`.

```js
// mock-openai.mjs — минимальный OpenAI-compatible SSE сервер для проверки чата.
import http from 'node:http'

const server = http.createServer(async (req, res) => {
  if (req.method !== 'POST' || !req.url?.endsWith('/chat/completions')) {
    res.writeHead(404, { 'Content-Type': 'text/plain' })
    res.end('not found')
    return
  }

  let raw = ''
  for await (const chunk of req) raw += chunk
  let body = {}
  try {
    body = JSON.parse(raw)
  } catch {
    /* пустое тело — не ошибка для mock */
  }

  const messages = Array.isArray(body.messages) ? body.messages : []
  const lastUser = [...messages].reverse().find((m) => m.role === 'user')
  const wantsTool = String(lastUser?.content ?? '').toLowerCase().includes('файл')

  res.writeHead(200, {
    'Content-Type': 'text/event-stream; charset=utf-8',
    'Cache-Control': 'no-cache',
    Connection: 'keep-alive',
  })

  const send = (payload) => res.write(`data: ${JSON.stringify(payload)}\n\n`)

  if (wantsTool) {
    send({
      id: 'chatcmpl-mock',
      object: 'chat.completion.chunk',
      choices: [{
        index: 0,
        delta: {
          tool_calls: [{
            index: 0,
            id: 'call_mock_1',
            type: 'function',
            function: { name: 'list_dir', arguments: '{"path":""}' },
          }],
        },
        finish_reason: null,
      }],
    })
    send({ choices: [{ index: 0, delta: {}, finish_reason: 'tool_calls' }] })
  } else {
    for (const part of ['Привет! ', 'Это локальный ', 'mock-ответ. ', 'Ключ не нужен.']) {
      send({
        id: 'chatcmpl-mock',
        object: 'chat.completion.chunk',
        choices: [{ index: 0, delta: { content: part }, finish_reason: null }],
      })
      await new Promise((resolve) => setTimeout(resolve, 120))
    }
    send({ choices: [{ index: 0, delta: {}, finish_reason: 'stop' }] })
  }

  res.write('data: [DONE]\n\n')
  res.end()
})

server.listen(8787, '127.0.0.1', () => {
  console.log('mock OpenAI endpoint: http://127.0.0.1:8787/v1')
})
```

Настройки IDE:

```text
Адрес API:  http://127.0.0.1:8787/v1
API-ключ:   sk-REPLACE_ME
Модель:     mock-model
```

Проверка:

1. Откройте любой проект (для инструментов).
2. Отправьте «привет» — придёт потоковый текстовый ответ.
3. Отправьте сообщение со словом «файл» — появится карточка `list_dir`; разрешите её и проверьте, что пришёл следующий ответ.
4. Повторите и нажмите «Отклонить»: mock получит результат «Отклонено пользователем» и завершит сценарий.

Сервер игнорирует `Authorization`, поэтому подходит любой непустой ключ. Он также не смотрит на `toolsEnabled` и может прислать tool calls даже при выключенных инструментах — это особенность mock, а не приложения. Никогда не вставляйте реальный ключ в примеры, скриншоты и коммиты.

## 9. Остановка, очистка, повтор

| Действие | Что происходит |
| --- | --- |
| «Остановить» | `ai:abort` → `AbortController.abort()`; стрим прекращается, `ai:done` с `ok: false`; в истории не появляется ошибка, если это была ручная остановка. Страховочный таймер 2,5 с завершает состояние, если main не ответил |
| «Очистить чат» | прерывает активный запрос (если есть) и очищает сообщения, ошибку, ожидающие инструменты |
| «Повторить» | доступен после ошибки; удаляет неудачный placeholder ассистента и повторяет запрос с текущей историей |
| смена языка/темы | на чат не влияет |

Во время стрима или ожидания инструментов новое сообщение не отправляется.

## 10. Ошибки

| Ситуация | Сообщение / поведение |
| --- | --- |
| не задан `baseUrl` | `Не указан адрес API (Настройки → ИИ)` |
| не задан ключ | `Не указан API-ключ (Настройки → ИИ)` |
| не задана модель | `Не указана модель (Настройки → ИИ)` |
| HTTP != 2xx | `API <status>: <detail>`; из JSON берётся `error.message` или `message`, текст обрезается до 500 символов |
| сеть/таймаут/DNS | текст исключения `fetch` в ошибке чата |
| ручная остановка | «Запрос остановлен» (не показывается как ошибка) |
| битая SSE-строка | пропускается; стрим продолжается |
| невалидные аргументы инструмента | карточка с ошибкой, выполнение недоступно |
| инструмент вернул ошибку | результат с ошибкой уходит модели как `role: tool`; карточка помечается «Ошибка» |
| нет проекта | карточки инструментов заблокированы: «Инструменты недоступны, пока не открыт проект» |

Проверка соединения ограничивается фактическим запросом: отдельной кнопки «Проверить ключ» нет. Если ответ пустой, проверьте, что сервер присылает SSE-строки `data:` и корректный `choices[0].delta`.

## Новые инструменты (версия 1.1)

> Все вызовы инструментов показываются в чате карточкой с кнопками «Разрешить» / «Отклонить».
> `update_plan` применяется сразу (это только отображение плана), остальные действия ждут решения пользователя.

### `edit_file` — точечное редактирование

| Параметр | Тип | Описание |
| --- | --- | --- |
| `path` | string | путь относительно проекта или абсолютный (внутри проекта/библиотек) |
| `old_text` | string | точный фрагмент для замены (включая отступы) |
| `new_text` | string | новый текст; пустая строка — удалить фрагмент |
| `replace_all` | boolean | заменить все вхождения (по умолчанию одно) |

Если точного совпадения нет, инструмент пробует сопоставление с игнорированием различий в пробелах.
При нескольких совпадениях без `replace_all` возвращается ошибка с просьбой добавить контекст.

### `list_dir` — дерево папок и файлов

`path`, `recursive` (по умолчанию false), `depth` (1–4). Для полной структуры проекта:
`{"path": ".", "recursive": true}`. Служебные папки (`node_modules`, `.git`, `dist`, `release`) пропускаются.

### Библиотеки

- `list_libraries` — имя, версия, автор, краткое описание и **абсолютный путь** каждой библиотеки
  (скетчбук `Документы\Arduino\libraries` + дополнительные папки из настроек).
- `read_file` / `edit_file` / `write_file` / `create_file` / `delete_file` принимают абсолютные пути внутри
  папок библиотек. Такие карточки помечаются «Вне папки проекта (библиотека)».
- Изменения библиотек выполняются только после подтверждения; удаление корневой папки запрещено.

### `run_python`

Параметры: `path` или `code`, `args`, `cwd`, `timeout_ms` (по умолчанию 60 с, максимум 180 с).
Запускается `python` (или `py -3`) из PATH. Вывод ограничен 40 000 символов, процесс убивается по тайм-ауту
вместе с дочерними. Без открытого проекта инструмент недоступен (рабочая папка — проект).

### `run_shell`

Параметры: `command`, `shell` (`powershell` по умолчанию | `cmd`), `cwd`, `timeout_ms`.
Выполняется `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -Command` либо `cmd.exe /c`.
В карточке показывается команда и красная пометка «Опасное действие».

### `web_search` и `web_fetch`

`web_search`: `query`, `max_results` (1–10). Провайдер выбирается в **Настройках → ИИ**:

| Провайдер | Ключ | Примечание |
| --- | --- | --- |
| DuckDuckGo | не нужен | бесплатно, но может ограничивать частые запросы |
| Brave Search API | нужен | стабильные результаты, ключ из brave.com/search/api |
| Tavily | нужен | ключ из tavily.com |

Для Brave/Tavily ключ хранится локально в `settings.json`. Если провайдер с ключом не сработал,
используется DuckDuckGo как резерв.

`web_fetch`: `url` (http/https). Возвращает текст страницы без HTML, до 30 000 символов.
Локальные и приватные адреса (`localhost`, `127.*`, `10.*`, `192.168.*`, `172.16–31.*`, `169.254.*`, `.local`)
запрещены.

### `update_plan` — план задачи

`{"title": "...", "steps": [{"title": "...", "status": "pending|in_progress|done|failed", "note": "..."}]}`.

План отображается над сообщениями: название, прогресс (`2 из 3`) и шаги с иконками статусов.
Модель обновляет план по ходу работы; пользователь видит, на каком шаге она находится.
Системная инструкция IDE просит ассистента начинать многошаговые задачи с плана.
