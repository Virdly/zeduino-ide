# Безопасность

## 1. Поддерживаемые версии

| Версия | Поддержка |
| --- | --- |
| 1.0.x | Да, исправления безопасности выпускаются для актуального релиза |
| < 1.0 | Нет |

Проект распространяется как portable-приложение без автообновления: исправление выходит новым релизом, установить его нужно вручную.

## 2. Как сообщить об уязвимости

**Не создавайте публичный Issue.**

Используйте приватный GitHub Security Advisory:

```text
https://github.com/USERNAME/zeduino-ide/security/advisories/new
```

Либо раздел **Security → Report a vulnerability** в репозитории. Если приватный канал недоступен, свяжитесь с мейнтейнером через GitHub (профиль в `package.json`) без публичного раскрытия деталей.

В сообщении укажите:

- версию ZedArduino IDE и версию Windows;
- затронутый компонент (IPC, AI-инструменты, файловые операции, монитор порта, сборка);
- шаги воспроизведения и ожидаемое/фактическое поведение;
- оценку влияния (что может сделать атакующий);
- PoC, если он безопасен и не содержит ваших реальных ключей/данных.

Мы постараемся подтвердить проблему и согласовать срок раскрытия. Пожалуйста, не публикуйте детали до выхода исправления.

## 3. Модель безопасности

Приложение локальное; оно не принимает входящих соединений и не имеет собственного сервера.

| Механизм | Реализация |
| --- | --- |
| Изоляция renderer | `contextIsolation: true`, `nodeIntegration: false`, `webSecurity: true`; renderer общается с ОС только через `window.api` |
| IPC | Фиксированный список каналов; ошибки нормализуются; произвольные команды через IPC не выполняются |
| Файлы проекта | `WorkspaceService.resolveInside` не выпускает путь за корень проекта |
| Инструменты ИИ | Каждый вызов требует явного одобрения пользователя; выполняется в main, не в renderer; проект должен быть открыт |
| Внешние ссылки | Разрешены только `http(s)`; открываются в системном браузере, новые окна Electron запрещены |
| Ключ ИИ | Хранится локально в `settings.json`; отправляется только на настроенный endpoint |
| Телеметрия | Отсутствует |

`arduino-cli` — внешняя программа, которую IDE находит или скачивает по действию пользователя. Она запускается с правами пользователя и не входит в поставку.

## 4. Что считается уязвимостью

- Обход проверки пути и чтение/запись/удаление файлов **вне** открытого проекта через IPC или инструменты ИИ.
- Выполнение инструмента ИИ без явного одобрения пользователя, подмена решения «Отклонить» на «Разрешить» или обход песочницы.
- Выполнение произвольного кода в renderer (XSS/RCE) из-за ответа модели, имени файла, содержимого проекта или Markdown-чата.
- Утечка API-ключа или содержимого файлов проекта в логи, тосты, события или сеть, кроме настроенного endpoint.
- Открытие `file://`, `javascript:` или иных небезопасных схем через ссылки приложения.
- Подмена загружаемого `arduino-cli`/архива без проверки (если вы найдёте практический сценарий MITM/подмены).
- Уязвимости зависимостей, которые эксплуатируются в контексте приложения (RCE/утечка данных), с воспроизведением.
- Обход ограничений загрузки файлов (например, path traversal в ZIP-установке библиотеки) с выходом за ожидаемые каталоги.

## 5. Что НЕ является уязвимостью

- **Компиляция и загрузка произвольного кода.** IDE предназначена для запуска компилятора и загрузки прошивок; выполнение кода скетча на подключённой плате — ожидаемая функциональность. Скетч может испортить железо или данные на устройстве — это ответственность пользователя.
- **Выполнение `arduino-cli` и компилятора.** Это внешние инструменты, запускаемые с правами пользователя; их поведение и уязвимости нужно сообщать в upstream-проекты. Если интеграция IDE усиливает проблему — сообщите нам.
- **Пользовательский AI-провайдер.** Настроенный endpoint получает промпт, историю и содержимое прочитанных файлов; политика хранения и качество ответов — зона провайдера. Локальный `http://` endpoint без TLS — осознанный выбор пользователя.
- **Локальное хранение ключа в открытом виде.** `settings.json` не шифруется; любой, у кого есть доступ к профилю Windows, может его прочитать. Это задокументировано в [AI](docs/AI.md#7-приватность-и-хранение-ключа). Защита профиля — средствами ОС.
- **Отсутствие подписи кода / предупреждение SmartScreen.** Сборка не подписана; это ограничение распространения, а не уязвимость (см. [PUBLISHING](docs/PUBLISHING.md#9-подпись-кода-и-smartscreen)).
- **Самоповреждение проекта.** Инструменты ИИ могут перезаписать или удалить файлы после одобрения; резервных копий нет. Не одобряйте действия, в которых не уверены; используйте систему контроля версий.
- **Модель ошибается или галлюцинирует.** Некорректный код/совет модели — не уязвимость IDE, если он не приводит к обходу описанных выше границ.
- **Атака с правами администратора/локального пользователя**, который уже может читать `settings.json`, менять файлы приложения или внедрять DLL. Защита от уже скомпрометированной ОС не входит в модель угроз.
- **Сетевые атаки на `arduino-cli` при установке ядер** (компрометация GitHub/зеркала) — вне контроля IDE, хотя сообщите, если IDE неверно обрабатывает результат.

## 6. Известные ограничения

- Проверка песочницы ИИ основана на `path.resolve` и сравнении префикса; `realpath`/канонизация симлинков не выполняется. Симлинк или junction внутри проекта теоретически может указывать за его пределы. Не открывайте недоверенные проекты с подозрительными ссылками; если найдёте практический сценарий эксплуатации — сообщите приватно.
- `delete_file` удаляет без корзины и может удалить каталог рекурсивно, если модель передала путь папки. Защита — обязательное подтверждение пользователя.
- Лимит чтения файла инструментом — 120 000 символов; файл больше 8 МБ не читается редактором.
- Настройки приложения и portable-сборка не защищены ACL сверх обычных прав профиля.

## 7. Рекомендации пользователям

- Скачивайте сборку только из GitHub Releases этого репозитория.
- Проверяйте контрольную сумму архива, если она опубликована.
- Используйте отдельный API-ключ с ограниченным бюджетом/правами; отзывайте его при подозрении на утечку.
- Для локальных моделей предпочитайте `127.0.0.1`; для удалённых — только HTTPS.
- Не открывайте чужие проекты со скриптами сборки, симлинками и неожиданными файлами.
- Держите Windows и `arduino-cli` обновлёнными.
- Перед одобрением `write_file`/`delete_file` прочитайте путь и аргументы в карточке.

## 8. Раскрытие

После исправления информация публикуется в release notes и/или GitHub Security Advisory. Пожалуйста, дайте время на выпуск обновления; проект не имеет программы bug bounty.
